# 0009 · Entitlements, billing and the anonymous claim

**Status:** accepted · 2026-11-16 (numbers and prices in `packages/core/src/plans.ts` are placeholders awaiting the owner)

**Decisions.**

1. **The plan is resolved on the server from the caller's identity, never from arguments.** `startExport` calls the pure `decideExport` (core) with the plan and this period's usage. Only an authenticated Clerk identity can hold a paid plan; an anon id is always free, even if the project it opens belongs to a paying user. The client can only choose `mode: "free"` (a downgrade). A request that needs a paid plan throws `ConvexError({ code: "paid_required", reason, freeAvailable })`; the paywall appears only on that answer, and only if the `billing` flag is on. **Enforcement is conditional:** the paywall rules apply only when the `billing` flag is on for the caller AND `STRIPE_SECRET_KEY` is set, i.e. when payment can actually be taken. Otherwise `startExport` behaves as before (watermark, silent clamp to the free cap, no minutes block, no `paid_required`) while still recording usage. Clients that send no `mode` (mobile) are therefore unaffected until billing is live.
2. **Usage** is rendered minutes per UTC calendar month. It is counted once, when a render job succeeds (`exports.usageCounted`), against whoever the export was charged to (`chargedUserId`, or the SHA-256 of the anon id). Signed-in usage lives in `entitlements`; anonymous usage in `anonUsage`. Minutes are checked at start and counted at success, so a burst of queued exports can overshoot the allowance slightly; accepted for now.
3. **Stripe by REST, no SDK.** `billing.checkout` (action) creates a Checkout session with `fetch` when `STRIPE_SECRET_KEY` is set and otherwise returns `{ configured: false }`. Price ids come from env. The webhook verifies `Stripe-Signature` (HMAC-SHA256 over `${t}.${rawBody}`, 5 minute tolerance, constant-time compare) with WebCrypto, then `applyStripeEvent` records the event id and applies it in one transaction, so replays change nothing. Handled: `checkout.session.completed` (plan or credit pack), `customer.subscription.updated` / `.deleted`. Subscriptions are matched by Stripe customer id, falling back to the `userId` we put in metadata.
4. **Clerk webhooks** (`user.created/updated/deleted`) are verified with Svix signatures over WebCrypto. `user.deleted` clears the email, drops the entitlement and marks the user; it does not delete projects or media (owner's call, below).
5. **The claim.** `account.claim({ anonId })` (authenticated) moves every project with that anon id and no owner user to the caller, along with its jobs. The anon id is a device-held secret, so presenting it is the proof; its format is validated as in `owner.ts`. Idempotent; never moves a project that already has an owner user; each call that moves something writes an `accountClaims` row (anon id stored hashed). After the claim the user reads the project without the anon id. The project keeps its `ownerAnonId`, so the original device still works signed out (but gets the free plan).
6. **"Your edit is ready"** (SendPulse SMTP API: OAuth client-credentials token, then `POST /smtp/emails`). Away signal: the editor sends a `presence.beat` every 20s while its tab is visible; someone is "watching" if a beat arrived in the last 45s. When an export succeeds, the owner is a signed-in user with an email, the `ready_email` flag is on and nobody is watching, a `notifications` row is queued and sent. Without SendPulse env the row reads "not sent · SendPulse not configured", so the path is observable.
7. **Flags** `accounts`, `billing`, `ready_email` (default off) gate the signup prompt, the paywall/checkout, and the email. Keys alone do not switch a feature on; the flag does.
8. **Sentry:** `@sentry/nextjs` init in client, server and edge files, each a no-op without a DSN; source maps upload only when `SENTRY_AUTH_TOKEN` is set. The Python worker initialises `sentry-sdk` only if `SENTRY_DSN` is set and the optional `sentry` extra is installed.

**Addendum · Phase 4 (Pro by request), 2026-11-17.**
- *Approval.* `/admin/access` (same `EYELORE_ADMIN_TOKEN` gate as `/funnel`) approves or declines `accessRequests`. Approve is one mutation: refuse at the seat cap (`EYELORE_PRO_SEATS`, default 100, malformed → 100), mark approved, add the lowercased email to the `pro` flag's allow list (row created `enabled: true, rolloutPct: 0`, so the allow list is the only way in), schedule the invite. Approving twice is a no-op; declining an approved request frees the seat and removes the email.
- *Invite.* An action mints `eci_` + 32 random bytes, stores only its SHA-256 on the request, and emails `/pro/checkout?token=…` through the shared `sendPulseEmail` helper (same honest "not sent · SendPulse not configured"). Resend mints a new link.
- *Checkout.* `access.proCheckout` needs a valid link, a signed-in Clerk account with the approved email, `STRIPE_SECRET_KEY` and the `billing` flag; it reuses `createStripeCheckout`. Pro is sold as the `creator` plan (`PRO_PLAN` in core) until the owner names a separate price.
- *Credits.* Plans carry a placeholder `monthlyCredits`; the webhook grants them at most once per UTC month (`entitlements.creditsPeriod`) on checkout and on a live `customer.subscription.updated` (a renewal), never on `past_due`. *Superseded by ADR 0014:* the grant is now a lot that ends with the month (no rollover), charges are reserved from generated seconds, and refunds go back lot by lot.
- *GPU gate.* `enqueueJob` (the only enqueue path) charges any job type outside the free CPU set (`hello`, `transcribe`, `autocut`, `reframe`, `render`) before waking a worker: the owner must be signed in, on the `pro` allow list, on a paid plan whose subscription is `active`/`trialing`, with enough credits; otherwise `ConvexError({ code: "pro_required" | "subscription_inactive" | "credits_required" })`. The charge is recorded in `creditCharges` and refunded once on final failure (no retries left, contract failure, last lease expiry). The allow-list check means buying `creator` through the export paywall alone does not unlock GPU work.

**Consequences.** Free and anonymous users can never get an unwatermarked or over-cap export by changing arguments (tests in `convex/around.test.ts`). Convex `auth.config.ts` now switches Clerk on when `CLERK_JWT_ISSUER_DOMAIN` is set, with no failure when it is not.
